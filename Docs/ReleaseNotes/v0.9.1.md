# LCE 0.9.1 — the release automation

The engine surface is unchanged — this is the shipping infrastructure.
0.9.1 is also the first release the automation made itself: a version
tag was pushed, and this release's three archives were built, gated,
and published by the new Release workflow.

## CI is now the full story

- **Push-time CI runs Debug AND Release on four platforms** — Windows
  (MSVC, /W4 /WX), Ubuntu (GCC), Ubuntu (Clang), and macOS (Apple
  Clang). The optimized, NDEBUG shape that ships is checked on every
  push, not only overnight.
- **The nightly** re-covers Release on all four platforms on a
  schedule.
- **The packaging gate** proves both Embedding paths — FetchContent via
  the doctor scaffold and find_package against the installed prefix —
  in Release, the configuration these archives ship in.

## Code scanning and the community files

- **CodeQL** scans the C++ on every push, every pull request, and
  weekly.
- **Issue templates** for bugs and feature requests are live, and
  **SECURITY.md** (private vulnerability reporting) plus
  **CONTRIBUTING.md** are in place.
- A **GitHub Pages** workflow renders the docs (enable once: Settings →
  Pages → Source: "GitHub Actions").

## The dev loop

- A Docker-based **Linux+GCC loop**
  (`Tools/scripts/linux-gcc-loop.sh`) reproduces the ubuntu-gcc leg
  before push — the leg that historically failed only on Linux.

## Version

0.9.1 everywhere: CMakeLists, Version.h, the doctor scaffold's GIT_TAG
pin, and the Embedding recipe.
