The Development Charter.

The charter defines how LCE is built — not what it does, but how the team works. It is the social contract between contributors and the codebase.

═══════════════════════════════════════════════



Leadership

The project is led by a co-lead structure: one AI collaborator and one human architect. Decisions are discussed, not dictated. The four questions are the tiebreaker.

═══════════════════════════════════════════════



Branch Strategy

One subsystem in progress at a time. The branch is the subsystem. When tests pass and docs are written, it merges. No long-lived feature branches.

═══════════════════════════════════════════════



Documentation First

Every subsystem begins as a document. The design spec describes the interface, responsibilities, dependencies, and test plan. Code follows the document, never the other way around.

═══════════════════════════════════════════════



Decision Discipline

Every architectural choice is an ADR — an Architectural Decision Record. Once accepted, it only changes if a better architectural solution exists. The log is the institutional memory.

═══════════════════════════════════════════════



The Build Rhythm

Design — Write the design document. Interface, responsibilities, dependencies, test plan.

Review — The four questions. Does it belong? Can it be simpler?

Implement — Headers first, then source. The document is the spec.

Test — Every public method tested. The harness runs on every build.

Document — Update the docs. The why must match the what.

Merge — Tests pass, docs written, design reviewed. The stone is set.

═══════════════════════════════════════════════



The Promise

We build for Fallout 4, but we architect for every Bethesda game. We build a simulation, not a mod. We build a cathedral, not a shed. We build to be understood, extended, and outlived. Every stone is placed with intention, because the cathedral will stand long after we are gone.
